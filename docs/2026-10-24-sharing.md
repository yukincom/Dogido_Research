# 本棚のリンク共有（2026-10-24）

トップページの「句集・あんちょこ・フォトブック」の下、右寄りにXとInstagramの共有アイコンを追加した。利用者が指定したフライヤーを変更せず、本棚の公開URLと一緒に用意する。

- アイコンを押すと、フライヤー・投稿文・URLが用意された共有パネルを開く。画像共有に対応する端末では、パネルの「画像とリンクを共有」からOSの共有画面を開き、利用者がXまたはInstagramを選ぶ。受け取るアプリによって投稿文やリンクの扱いは異なる。
- 非対応時は、フライヤーのプレビュー、画像保存、投稿文とURLのコピーを表示する。Xでは投稿文・URLを入れた投稿画面を開く。Instagramでは保存した画像を「作成」で選び、コピーした文を貼り付ける。
- アカウント連携や自動投稿は行わない。共有画面の起動を投稿成功として扱わない。取消時に再送・別アプリ起動をしない。
- X等のリンクプレビュー用に、このフライヤーをOpen GraphとTwitter Cardへ指定した。実際のカード表示や更新時期は共有先に依存する。

共有内容は固定の公開本棚URL、紹介文、確認済み画像だけ。現在の検索語・表示中の相談・端末内のパスは含めない。`connect-src 'none'` を維持し、第三者SDK、API、追跡処理は追加していない。`share-image.js` は同じ原画像をFileとして同期で用意するためのデータで、ボタン操作からの共有開始を非同期ダウンロードで遅らせない。公開前に保存画像・File用bytes・確認記録のhashを一致させる。

仕様上、Web Shareの共有先はブラウザーとOSが提供し、サイトから特定のSNSを強制選択できない。参考: [W3C Web Share API](https://www.w3.org/TR/web-share/)、[MDN navigator.share](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/share)。

検証: Python 33件・Node 8件と配布検査が成功。共有APIへ渡すJPEGの一致、非対応・取消・失敗の分岐、公開URLだけを渡すことを模擬APIで確認した。ブラウザーではトップページ下部の配置、XとInstagramの共有パネル、フライヤー表示、投稿文とURLのコピーを確認した。OS共有先での画像添付完了と、各SNSへの実投稿は未検証。
